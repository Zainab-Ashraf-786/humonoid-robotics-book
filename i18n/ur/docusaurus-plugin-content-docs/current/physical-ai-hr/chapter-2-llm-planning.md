# ایل ایل ایم-مبنی کوگنیٹو منصوبہ بندی

یہ سیکشن یہ تلاش کرتا ہے کہ بڑے زبانی ماڈلز (LLMs) ہیومنوڈ روبوٹس کے لیے بالائی سطح کی کوگنیٹو منصوبہ بندی کیسے فراہم کر سکتے ہیں، قدرتی زبان کی سمجھ کو جسمانی ایکشن انجام دہی کے ساتھ جوڑنا۔ ہم یہ مطالعہ کریں گے کہ LLMs کو کس طرح جامد سسٹم کے ساتھ ضم کیا جا سکتا ہے تاکہ زیادہ قدرتی انسان-روبوٹ تعامل اور لچکدار رویے کی اصلاح کو فعال کیا جا سکے۔

## سیکھنے کے اہداف

اس باب کو مکمل کرنے کے بعد، آپ:
- سمجھیں گے کہ LLMs روبوٹس کے لیے بالائی سطح کی کوگنیٹو منصوبہ بندی کیسے فراہم کر سکتے ہیں
- جانیں گے کہ روبوٹ کنٹرول کے لیے قدرتی زبان کے ویتر کیسے نافذ کرنا ہے
- کوگنیٹو آرکیٹیکچر کو ڈیزائن کرنے کے قابل ہوں گے جو زبان اور ایکشن کے درمیان پل فراہم کرے
- LLMs کے فزیکل سسٹم کے ساتھ ضم کرنے کی چیلنجز اور مواقع کو سمجھیں گے
- اس بات کی قدر کریں گے کہ LLMs ہیومنوڈ روبوٹس میں جامد عقل کو کیسے بہتر بنا سکتے ہیں
- LLM-مبنی منصوبہ بندی کو روبوٹکس ایپلی کیشنز کے لیے توثیق اور بہتر بنانے کے طریقے جانیں گے

## ایل ایل ایم کوگنیٹو منصوبہ بندی کا تعارف

### ایل ایل ایم کوگنیٹو منصوبہ بندی کیا ہے؟

ایل ایل ایم کوگنیٹو منصوبہ بندی روبوٹکس سسٹم کے لیے بالائی سطح کی ت_REASONING_ اور منصوبہ بندی کی صلاحیتیں فراہم کرنے کے لیے بڑے زبانی ماڈلز کے استعمال کو اشارہ کرتا ہے۔ روایتی علامتی منصوبہ بندی کے نقطہ نظر کے برعکس جن کے لیے صریح ریاست کی نمائندگی اور ایکشن کی تعریف کی ضرورت ہوتی ہے، LLMs قدرتی زبان کے حکم کی تشریح کر سکتے ہیں اور انہیں قابل انجام روبوٹکس ایکشن کی ترتیب میں تقسیم کر سکتے ہیں۔

**اہم خصوصیات:**
- **قدرتی زبان کا ویتر**: قدرتی زبان میں بیان کردہ حکم کو سمجھتا ہے
- **دنیا کا علم**: LLMs میں کوڈ شدہ وسیع علمی بنیادوں کا فائدہ اٹھاتا ہے
- **لچکدار منصوبہ بندی**: واضح پروگرامنگ کے بغیر نئی صورتحال کے لیے منصوبے تیار کرتا ہے
- **سیاق کی آگاہی**: صورتحال کا سیاق اور جگہ کے رشتے برقرار رکھتا ہے
- **انسان جیسا ت_REASONING_**: جسمانی اشیا اور ایکشن کے بارے میں عام سمجھ کا ت_REASONING_ کرتا ہے

### فزیکل ای آئی میں LLMs کا کردار

LLMs فزیکل ای آئی کو یہ فراہم کر کے مکمل کرتے ہیں:
- **بالائی سطح کی ت_REASONING_**: قدرتی زبان میں بیان کردہ اہداف کو سمجھنا
- **علم کا انضمام**: منصوبہ بندی کے لیے علم کو رسائی فراہم کرنا
- **عام سمجھ کا ت_REASONING_**: جسمانی کاموں کے لیے روزمرہ کا ت_REASONING_ لاگو کرنا
- **لچکدار اصلاح**: زبانی فیڈ بیک کی بنیاد پر منصوبوں کو اصلاح کرنا
- **سماجی تعامل**: انسانوں کے ساتھ قدرتی مواصلت کو فعال کرنا

### روایتی منصوبہ بندی کے نقطہ نظر سے ممیزات

روایتی روبوٹکس منصوبہ بندی کے لیے اکثر ضرورت ہوتی ہے:
- صریح ریاست کی جگہ کی تعریف
- ہاتھ سے لکھے گئے ایکشن کی نمائندگی
- ڈومین-مخصوص منصوبہ ساز
- علامتی ہدف کی نمائندگی
- تعینات انجام دہی

LLM-مبنی منصوبہ بندی فراہم کرتا ہے:
- قدرتی زبان ہدف کی تصریح
- ایکشن کے رشتے کا سیکھا ہوا علم
- جامع مقصد کا ت_REASONING_
- جسمانی دنیا کی عام سمجھ
- نئی صورتحال کے لیے لچکدار اصلاح

## ایل ایل ایم انضمام آرکیٹیکچر

### کوگنیٹو آرکیٹیکچر کے نمونے

#### براہ راست میپنگ آرکیٹیکچر
سادہ ترین نقطہ نظر میں، LLMs براہ راست قدرتی زبان کو روبوٹ ایکشن میں میپ کرتے ہیں:
```
قدرتی زبان کا حکم → ایل ایل ایم → ایکشن کی ترتیب → روبوٹ انجام دہی
```

**فوائد:**
- نافذ کرنا آسان
- حکم سے ایکشن تک براہ راست راستہ
- سادہ حکم کے لیے کم تاخیر
-
**نقصانات:**
- پیچیدہ متعدد اقدام کاموں کا کم اچھا سامنا
- روبوٹ کی حالت کا محدود ادراک
- منصوبے کی اصلاح کا کوئی موقع نہیں
- محفوظ انجام دہی کو یقینی بنانا مشکل

#### سلسلہ وار منصوبہ بندی آرکیٹیکچر
ایک زیادہ جامع نقطہ نظر سلسلہ وار تقسیم کا استعمال کرتا ہے:
```
بالائی سطح کا حکم → ایل ایل ایم (تقسیم) → ذیلی اہداف → روایتی منصوبہ ساز → ایکشن → روبوٹ
```

**فوائد:**
- ایل ایل ایم کے دنیا کے علم اور روایتی منصوبہ ساز کی قابل اعتمادی دونوں کا فائدہ اٹھاتا ہے
- بالائی سطح کی ت_REASONING_ کو کم سطح کی انجام دہی سے الگ کرتا ہے
- انجام دہی سے پہلے منصوبوں کی توثیق کی اجازت دیتا ہے
- بہتر خرابی کے سامنا اور بازیابی کو فعال کرتا ہے

**نقصانات:**
- زیادہ پیچیدہ آرکیٹیکچر
- ایل ایل ایم-تیار کردہ ذیلی اہداف اور منصوبہ ساز کی صلاحیتوں کے درمیان ممکنہ عدم مطابقت
- متعدد عمل کے اقدامات کی وجہ سے تاخیر میں اضافہ

#### بندش والی آرکیٹیکچر
سب سے جدید نقطہ نظر مسلسل فیڈ بیک کو شامل کرتا ہے:
```
حکم → ایل ایل ایم (منصوبہ) → منصوبہ انجام دہندہ → روبوٹ ایکشن → تاثر → ایل ایل ایم (حالت کی تجدید) → منصوبہ کی اصلاح
```

**فوائد:**
- انجام دہی کے فیڈ بیک کی بنیاد پر مسلسل منصوبہ اصلاح
- غیر متوقع صورتحال کا قدرتی سامنا
- عدم یقینی میں بہتر مصلوبیت
- بہتر انسان-میں-لوپ انضمام

**نقصانات:**
- نافذ اور توثیق کرنا سب سے پیچیدہ
- لامحدود لوپ یا لہروں کا امکان
- مہارت مند منصوبہ نگرانی اور انجام دہی کے سسٹم کی ضرورت ہوتی ہے

### ROS 2 کے ساتھ انضمام کے نقاط

LLM کوگنیٹو منصوبہ بندی سسٹم ROS 2 کے ساتھ متعدد سطحوں پر ضم ہو سکتے ہیں:

#### ایکشن ویتر انضمام
LLMs ایکشن گولز تیار کر سکتے ہیں جو ROS 2 ایکشن سرور کو بھیجے جاتے ہیں:
```python
import rclpy
from rclpy.action import ActionClient
from geometry_msgs.msg import Pose
from nav2_msgs.action import NavigateToPose

class LLMNavigationPlanner:
    def __init__(self, llm_interface):
        # ... شروع کاری کوڈ ...
        self.nav_client = ActionClient(self, NavigateToPose, 'navigate_to_pose')

    def execute_navigation_command(self, command_text):
        # حکم کو تحلیل کرنے کے لیے LLM کا استعمال کریں
        target_location = self.llm_interface.parse_location(command_text)

        # نیویگیشن ہدف تیار کریں
        goal_msg = NavigateToPose.Goal()
        goal_msg.pose = target_location

        # ROS 2 نیویگیشن سسٹم کو بھیجیں
        self.nav_client.send_goal_async(goal_msg)
```

#### سروس انضمام
LLMs مخصوص صلاحیتوں کے لیے ROS 2 سروس کو کال کر سکتے ہیں:
```python
import rclpy
from std_srvs.srv import Trigger
from example_interfaces.srv import SetBool

class LLMServicePlanner:
    def __init__(self, llm_interface):
        # ... شروع کاری کوڈ ...
        self.emergency_stop_cli = self.create_client(SetBool, 'emergency_stop')
        self.calibrate_sensors_cli = self.create_client(Trigger, 'calibrate_sensors')

    def process_command(self, command_text):
        parsed_intent = self.llm_interface.parse_intent(command_text)

        if parsed_intent == "emergency_stop":
            request = SetBool.Request(data=True)
            self.emergency_stop_cli.call_async(request)
        elif parsed_intent == "calibrate":
            request = Trigger.Request()
            self.calibrate_sensors_cli.call_async(request)
```

#### ٹاپک-مبنی نگرانی
LLM سسٹم ROS 2 ٹاپکس کو ماحولیاتی سیاق کے لیے نگرانی کر سکتے ہیں:
```python
from sensor_msgs.msg import LaserScan
from nav_msgs.msg import Odometry

class LLMContextAwarePlanner:
    def __init__(self, llm_interface):
        # ... شروع کاری کوڈ ...
        self.odom_sub = self.create_subscription(Odometry, 'odom', self.odom_callback, 10)
        self.scan_sub = self.create_subscription(LaserScan, 'scan', self.scan_callback, 10)

        self.current_pose = None
        self.environment_state = None

    def odom_callback(self, msg):
        self.current_pose = msg.pose.pose
        self.update_llm_context()

    def scan_callback(self, msg):
        self.environment_state = self.process_environment(msg)
        self.update_llm_context()

    def update_llm_context(self):
        # موجودہ روبوٹ کی حالت اور ماحول کے ساتھ LLM کو اپ ڈیٹ کریں
        context = {
            'robot_pose': self.current_pose,
            'environment': self.environment_state
        }
        self.llm_interface.update_context(context)
```

## روبوٹکس کے لیے قدرتی زبان کی پروسیسنگ

### حکم کی تحلیل کی تکنیکیں

#### ٹیمپلیٹ-مبنی تحلیل
وہ ایپلی کیشنز کے لیے جن میں ازسبق حکم کا لغز موجود ہے:
```
حکم: "کچن میں جائیں اور مجھے ایک پانی کی بوتل لائیں"
تحلیل شدہ ساخت:
{
  "primary_goal": "fetch_object",
  "location": "kitchen",
  "object": "water bottle",
  "recipient": "me"
}
```

**فوائد:**
- تعینات تحلیل
- توثیق اور ڈیبگ کرنا آسان
- کلیدی معلومات کا درست انخلا
- محفوظیت سے متعلق ایپلی کیشنز کے لیے اچھا

**نقصانات:**
- ازسبق حکم کی ساختوں تک محدود
- نئی ترتیبات کو سنبھال نہیں سکتا
- دستی ٹیمپلیٹ تخلیق کی ضرورت
- غیر متوقع ان پٹ کے لیے ناپائیدار

#### LLMs کے ساتھ سیمینٹک تحلیل
حکم کے مطلب کو سمجھنے کے لیے LLMs کا استعمال:
```
ان پٹ: "کیا آپ براہ کرم کچن میں جا کر مجھے ایک پانی کی بوتل لے کر دے سکتے ہیں؟"
LLM آؤٹ پٹ:
{
  "intent": "fetch_item",
  "destination": "kitchen",
  "item": "water_bottle",
  "delivery_target": "user_current_location",
  "politeness": "formal_request",
  "priority": "medium"
}
```

**فوائد:**
- متغیر قدرتی زبان کے اظہار کو سنبھالتا ہے
- لہجے اور سیاق کو قبضہ میں لیتا ہے
- نامعلوم حکم کی ترتیبات پر عام کرتا ہے
- ضمنی معلومات نکال سکتا ہے

**نقصانات:**
- ٹیمپلیٹ نقطہ نظر کے مقابلے میں کم تعینات
- غلط تشریح کا امکان
- آؤٹ پٹ کی مہذب توثیق کی ضرورت
- سادہ تحلیل کے مقابلے میں سست ہو سکتا ہے

### جگہ اور سیاق کی سمجھ
LLMs کو مؤثر روبوٹکس منصوبہ بندی کے لیے جگہ کے رشتے اور سیاق کو سمجھنا چاہیے:

#### جگہ کے ت_REASONING_ کی مثالیں
```
حکم: "ک sofa کے پیچھے جائیں اور وہاں انتظار کریں"
LLM سمجھ:
- "پیچھے" کا مطلب رشتہ دار مقام کا اشارہ ہے
- "sofa" کو روبوٹ کے نقشے میں مقامی کرنا ضروری ہے
- "انتظار" کا مطلب اگلے حکم کے لیے نگرانی کے ساتھ روکنا ہے
- روبوٹ کو sofa کے رشتے میں مقام پر جانا ضروری ہے
```

#### سیاقی گراؤنڈنگ
```
پچھلا حکم: "5 منٹ میں لیونگ روم میں ملیں"
موجودہ حکم: "حالت کیا ہے؟"
LLM سمجھ:
- "حالت" انتظار کے کام کا اشارہ کرتا ہے
- "وہاں" لیونگ روم کا اشارہ کرتا ہے (پچھلے سیاق سے)
- روبوٹ کو موجودہ حالت اور گنتی کی اطلاع دینی چاہیے
```

### ابہام اور وضاحت کا سامنا
LLM-مبنی سسٹم ابہام والے حکم کو پہچاننا چاہیے اور وضاحت کی درخواست کرنا چاہیے:

```python
def parse_and_validate_command(self, command_text):
    parsed = self.llm_interface.parse_command(command_text)

    # ابہام کی جانچ کریں
    if self.has_ambiguity(parsed):
        clarification_request = self.generate_clarification(parsed)
        return {
            "status": "need_clarification",
            "request": clarification_request,
            "parsed": parsed
        }

    # منصوبے کی قابلیت کی توثیق کریں
    if not self.is_plan_feasible(parsed):
        return {
            "status": "impossible",
            "reason": "constraint_violation",
            "suggestion": self.suggest_alternative(parsed)
        }

    return {
        "status": "ready_to_execute",
        "parsed": parsed
    }

def has_ambiguity(self, parsed_command):
    # ابہام والے حوالہ جات کی جانچ کریں
    if "it" in parsed_command.get("objects", []) and not self.can_resolve_reference(parsed_command):
        return True

    # متعدد تشریحات کی جانچ کریں
    if len(parsed_command.get("potential_locations", [])) > 1:
        return True

    return False
```

## کوگنیٹو منصوبہ بندی الگورتھم

### LLMs کے ساتھ سلسلہ وار کام کے نیٹ ورکس (HTNs)
LLMs پیچیدہ کاموں کی HTN-جیسی تقسیم تیار کر سکتے ہیں:

```
ہدف: "صبح کا کافی تیار کریں"
LLM تقسیم:
1. کچن میں جائیں
2. کافی میکر کو تلاش کریں
3. کافی کی فراہمی تلاش کریں
   a. کافی کے بیج کے برتن کی جانچ کریں
   b. پانی کے ذخیرے کی جانچ کریں
   c. فلٹر کی دستیابی کی تصدیق کریں
4. کافی میکر تیار کریں
   a. پانی کے ذخیرے کو بھریں
   b. کافی کے بیج/گراؤنڈ شامل کریں
   c. فلٹر داخل کریں
5. کافی تیار کرنے کا عمل انجام دیں
   a. کافی میکر شروع کریں
   b. کافی تیار کرنے کی پیشرفت کی نگرانی کریں
   c. مکمل ہونے کا انتظار کریں
6. کافی پیش کریں
   a. پیش کرنے کے مقام پر جائیں
   b. کافی کو کپ میں ڈالیں
   c. صارف کو پہنچائیں
```

### کلاسیکل منصوبہ بندی کے ساتھ انضمام
LLMs بالائی سطح کے اہداف کو کلاسیکل منصوبہ ساز کے لیے مناسب ذیلی مسائل میں تقسیم کر سکتے ہیں:

```python
class LLMClassicalPlanner:
    def __init__(self):
        self.llm = LLMInterface()
        self.classical_planner = ClassicalPlanner()

    def solve_task(self, natural_language_task):
        # کام کو تقسیم کرنے کے لیے LLM کا استعمال کریں
        subtasks = self.llm.decompose_task(natural_language_task)

        plan_sequence = []
        for subtask in subtasks:
            if self.is_primitive_action(subtask):
                # براہ راست انجام دیں
                plan_sequence.append(subtask)
            else:
                # نیویگیشن/جسمانی مینیپولیشن کے لیے کلاسیکل منصوبہ ساز کا استعمال کریں
                classical_problem = self.convert_to_classical_problem(subtask)
                subplan = self.classical_planner.solve(classical_problem)
                plan_sequence.extend(subplan)

        return self.reconcile_plans(plan_sequence)
```

### نگرانی-اور-دوبارہ منصوبہ بندی انضمام
LLM منصوبہ بندی جو انجام دہی کی نگرانی کرتی ہے اور ضرورت کے مطابق دوبارہ منصوبہ بندی کرتی ہے:

```python
class MonitorAndReplanController:
    def __init__(self):
        self.llm = LLMInterface()
        self.robot_control = RobotControlInterface()
        self.perception_system = PerceptionSystem()

    def execute_command(self, command):
        # ابتدائی منصوبہ تیار کریں
        plan = self.llm.generate_plan(command)
        plan_index = 0

        while plan_index < len(plan):
            current_action = plan[plan_index]

            # ایکشن انجام دیں
            execution_result = self.robot_control.execute_with_monitoring(current_action)

            if execution_result.success:
                # اگلے ایکشن پر جائیں
                plan_index += 1
            else:
                # موجودہ حالت حاصل کریں اور دوبارہ منصوبہ بندی کریں
                current_state = self.perception_system.get_current_state()
                remaining_goal = self.extract_remaining_goal(plan, plan_index)

                replanned = self.llm.replan(remaining_goal, current_state, execution_result.failure_reason)
                plan = self.merge_plans(plan[:plan_index], replanned)
```

### محفوظی اور توثیق کی پرتیں

```python
class SafeLLMPlanner:
    def __init__(self):
        self.llm = LLMInterface()
        self.safety_validator = SafetyValidator()
        self.robot_model = RobotModel()

    def generate_plan(self, command):
        # ایل ایل ایم سے ابتدائی منصوبہ حاصل کریں
        candidate_plan = self.llm.generate_action_sequence(command)

        # ہر ایکشن کی توثیق کریں
        validated_plan = []
        for action in candidate_plan:
            if self.safety_validator.is_safe(action, self.robot_model):
                validated_plan.append(action)
            else:
                safe_alternative = self.safety_validator.propose_alternative(action)
                if safe_alternative:
                    validated_plan.append(safe_alternative)
                else:
                    raise UnsafePlanException(f"کے لیے محفوظ متبادل نہیں ملا: {action}")

        return validated_plan
```

```python
from functools import lru_cache

class CachedLLMPlanner:
    def __init__(self, cache_size=128):
        self.llm = LLMInterface()
        self.cache = LRUCache(maxsize=cache_size)

    @lru_cache(maxsize=128)
    def generate_cached_plan(self, command_hash):
        # معیاری حکم کا ہیش
        command = self.reverse_hash(command_hash)
        return self.llm.generate_action_sequence(command)
```

```python
class AdaptiveLLMPlanner:
    def __init__(self):
        self.llm = LLMInterface()
        self.plan_library = PlanLibrary()

    def generate_plan(self, new_command):
        # مشابہ گزشتہ منصوبوں کو تلاش کریں
        similar_plans = self.plan_library.find_similar_plans(new_command)

        if similar_plans:
            # موجودہ منصوبہ کو نئے سیاق کے لیے اصلاح کریں
            adapted_plan = self.adapt_plan(similar_plans[0], new_command)
            return adapted_plan
        else:
            # مکمل طور پر نیا منصوبہ تیار کریں
            return self.llm.generate_action_sequence(new_command)
```

LLM کوگنیٹو منصوبہ بندی انسانی ارادوں اور روبوٹ ایکشن کے درمیان قدرتی ویتر فراہم کرتی ہے۔ بالائی سطح کی ت_REASONING_ کے لیے بڑے زبانی ماڈلز کا فائدہ اٹھاتے ہوئے، ہیومنوڈ روبوٹس پیچیدہ قدرتی زبان کے حکم کو سمجھ سکتے ہیں اور مناسب جسمانی رویے تیار کر سکتے ہیں۔ کامیاب انضمام کی کلید LLMs کی لچک اور دنیا کے علم کو روبوٹ کنٹرول کی محفوظی اور قابل اعتمادی کی ضروریات کے ساتھ متوازن کرنا ہے۔

یہ نقطہ نظر LLMs کی قدرتی زبان کی سمجھ اور دنیا کے علم کو ضم کرتا ہے:
- قابل اعتماد انجام دہی کے لیے روایتی منصوبہ ساز سسٹم
- محفوظ آپریشن کے لیے محفوظی کی توثیق کی پرتیں
- محفوظ جائزہ کے لیے سیمولیشن ماحول
- مسلسل نگرانی اور اصلاح

## اگلے اقدامات

اگلا باب سیمولیشن-سے-حقیقت میں منتقلی کی تکنیکوں کو تلاش کرتا ہے، جو حقیقی دنیا کے ہیومنوڈ روبوٹس میں ایل ایل ایم کوگنیٹو منصوبہ بندی کو لاگو کرنے کے لیے اہم ہے۔ سیکھے گئے رویوں اور تصدیق شدہ منصوبوں کو سیمولیشن سے حقیقت میں منتقل کرنے کا طریقہ سمجھنا انسانی ماحول میں مؤثر طریقے سے کام کرنے والے قابل ہیومنوڈ سسٹم تخلیق کرنے کے لیے ضروری ہوگا۔

آپ سیکھیں گے کہ LLM منصوبہ بندی کو محفوظ طریقے سے جانچنے، محفوظی کے پروٹوکول کی توثیق کرنے، اور روبوٹس کو حقیقی دنیا میں قابل اعتماد طریقے سے کام کرنے کے قابل بنانے والی مضبوط منتقلی کی تکنیکوں کو تیار کرنے کے لیے سیمولیشن ماحول کا استعمال کیسے کرنا ہے۔
